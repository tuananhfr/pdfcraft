# ERPCons changes

This branch (`erpcons`) is the ERPCons Văn phòng fork of [PdfCraft](https://github.com/storytold/pdfcraft), based on PdfCraft by the ArtCraft team, licensed MIT OR Apache-2.0 (see `LICENSE-MIT`, `LICENSE-APACHE`, `NOTICE`). Changes from upstream `main` (Apache-2.0 §4b):

- (both) Confirm saving changes to a signed PDF on every save path (Save, Save As, web download; CLI `--acknowledge-signatures`, automation `acknowledgeSignatures` returning `signaturesAffected`), refuse in-place saves under a no-changes certification, and admit opened PDFs against a platform memory budget (normal, light read-only with a notice, or refused) with byte-budgeted canvas rasters and undo history.
- (both) Add accessible 44-point Undo/Redo toolbar controls and transaction ids/timestamps in history summaries, preserve history across draft/save, and brand the web app as PDF – ERPCons.
- Point the website links (About, installers, release notes) to https://office.erpcons.ai; app ids keep the `vn.erpcons.*` form.
- (desktop) Translate native self-update messages in all catalogues required by UI coverage tests, preserving placeholders and the product name.
- (desktop) Check signed ERPCons updates at startup, offer verified self-updates with save/cancel protection, and remember automatic-check and skipped-version preferences; explain the Windows MSI installation permission prompt before restarting and wait for explicit MSI installation confirmation.
- (desktop) Use the ERPCons PDF artwork for Windows PDF file icons, retaining resource 2 and all existing icon sizes; macOS already uses the ERPCons app icon for PDF documents.
- (desktop) Build unsigned Windows, ad-hoc signed universal macOS and Linux desktop installers in a dedicated GitHub Actions workflow, publish tagged releases with fixed download names and checksums, and accept ERPCons update tags.
- (desktop) Complete update-check translations and Lithuanian catalog coverage, preserving diagnostic placeholders and plural forms.
- (desktop) Brand the native app and installers as PDF – ERPCons, with ERPCons icons, application id and isolated settings paths.
- (desktop) Copy PDF text as escaped HTML paragraphs with a plain-text alternative, preserving copy-permission checks and falling back to plain text if rich clipboard writing fails.
- (desktop) Translate update-check errors and control-file guidance into Vietnamese, using the selected interface language.
- (desktop) Default to Vietnamese when no language is saved, respect saved and command-line choices, and atomically save language changes immediately.
- (both) At window widths up to 480 points, the quick tool rail has its own space beside the page viewport so it no longer hides page text; wider layouts are unchanged.
- (both) Single-document and multi-document save confirmation dialogs fit within the screen with at least 16-point side margins, keeping wrapped text and action buttons reachable on phones.

- (both) Export to Word preserves visual line breaks within the existing paragraph groups and writes known PDF font families, including subset/PostScript name normalization, into Word text runs without embedding fonts.
- (web) OCR recognition commands are hidden through the existing platform availability filter; direct OCR entry points explain that OCR is unavailable on the web and suggest the desktop app, while desktop behaviour is unchanged.
- (both) Form fields, text boxes and Add text write Vietnamese and other characters covered by the bundled Inter face using an embedded TrueType subset with Unicode copy/search mappings and real advance widths; WinAnsi text keeps its existing font path and unsupported characters keep the existing warning/refusal.
- (web) PDF saves time out after 60 seconds, show Save failed and offer Download of the pending PDF bytes while keeping the document unsaved; late callbacks are ignored and subsequent saves download instead of writing to the uncertain destination again.
- (web) Closing the last open document calls the optional ERP shell's no-argument window.erpEditorClosed hook once; closing other documents or an already empty editor does not call it.
- (both) Export to Word asks once before writing when the document has form fields, annotations/comments, signature fields or PDF encryption/permissions, lists their losses and counts plus possible layout changes, and offers Export anyway / Cancel. Clean text PDFs export without the warning.
- (both) PDF selection Copy and annotation Copy text now use the same copy-permission guard as Ctrl+C and Copy Image, showing the existing refusal notice without writing restricted content to the clipboard.
- (web) Create from clipboard reads plain text and PNG/JPEG images through the browser clipboard API; denied reads show a localized notice suggesting Ctrl+V. Desktop clipboard reading is unchanged.
- (web) Copying PDF text writes escaped HTML paragraphs alongside plain text with ClipboardItem, falling back to plain text when rich clipboard writes are unavailable or rejected.
- Removed the ArtCraft logos and marks (`docs/brand/` and their ATTRIBUTION entries) and every link to the ArtCraft Discord and getartcraft.com, as the ArtCraft brand terms require for forks: title-bar Discord button, home-screen community card, About dialog, Help menu entries, CLI and MCP server info, README. The README screenshot was regenerated without the mark.
- About now reads "ERPCons Văn phòng — dựa trên PdfCraft của nhóm ArtCraft. MIT OR Apache-2.0."; Help ▸ "PdfCraft on GitHub" and the releases page point at this fork.
- Help ▸ "Check for updates…" is not in the web build's menu.
- Dropped the translations of the removed strings.
- Web draft autosave for the ERPCons Văn phòng shell (`crates/ui-egui/src/drafts.rs`, `apps/pdfcraft-web/src/main.rs`): unsaved documents are handed to `window.erpDrafts` (format `pdf`, the working bytes) after 2.5 s idle / 30 s of continuous edits and when the page is hidden, removed once saved, undone to saved or closed, and drafts the shell restores reopen unsaved under their key. Off without `window.erpDrafts` and in `?host=parent` mode; the desktop recovery store is unchanged.
- Vietnamese interface (`crates/ui-egui/src/i18n/vi.tsv`, code `vi`, one plural form) and Vietnamese date names (`crates/engine/src/dates.rs`), translated clean-room with Office-style Vietnamese command names (feature names only). The web build opens in Vietnamese unless the user picked another language and remembers the choice in `localStorage` key `erpcons-ui-language`, which the other ERPCons editors share (`apps/pdfcraft-web/src/language.rs`).
- Office-style keys: F1 opens Help ▸ Keyboard shortcuts, F12 saves as (with Ctrl+Shift+S), Ctrl+Y redoes (with Ctrl+Shift+Z), and plain `+` / `=` and `-` zoom in and out while no text field or text on the page is being typed in. The shortcuts dialog lists each command's alternate keys in its row and has a search box that filters by command name (in the UI language or English) or by key.
- Honest saving on the web (`crates/ui-egui/src/web_save.rs`): a document counts as saved only once the browser reports the file written, as it was written, so a cancelled save picker, a failed write or edits made while the picker is open leave it unsaved (and its office-shell draft kept). Save As uses the browser's save picker (Chrome, Edge), suggesting the current name and adopting the name picked for the tab, the window title and the next Save, which writes to that file again without asking; browsers without the picker (Firefox, Safari) ask for the file name in an in-app prompt (`.pdf` kept) before downloading. Save on a document never saved in the session behaves as Save As.
- Signed files keep their signatures (spec OF-14; `crates/engine/src/certification.rs`, `crates/ui-egui/src/cert_guard.rs`, `crates/sign/src/mdp.rs`): before Save or Save As, the unsaved edits are classified against the file as last saved in the validator's DocMDP words; edits a certification does not permit, or that change a field a signature locks (FieldMDP `/Reference` or the field's `/Lock`), hold the save in a dialog naming the signer and date with only "Save a copy…" and "Cancel", and a copy is never written over the signed original (`doc_save` refuses it too). A no-changes (P=1) certification shows a bar, refuses editing tools, edits and signing as they are used, and keeps viewing, printing, copying and Save As. Approval signatures without a lock never block.
- `deny.toml` ignores the RustSec advisories published in October 2026 that do not reach PdfCraft, each with its reason: the unmaintained zbus 5 helper crates (RUSTSEC-2026-0370…0372; Linux D-Bus only). rustls is on 0.23.46, which fixes RUSTSEC-2026-0346…0349.
- Phones and tablets (`crates/ui-egui/src/narrow.rs`, `bar_fit.rs`, `touch_page.rs`): below `NARROW_WIDTH` (600 points of window width; a tablet in portrait stays wide) the Tools pane and the right panel fold away once as the window crosses the breakpoint, a panel opened on the phone stays open, and widening restores the wide-state choice, which is also what the settings keep (`right_panel_closed` is untouched). At that width the tab strip and the mode bar shed controls by measured width instead of overlapping (search box to an icon, Menu to its icon, the modes to a picker naming the current one, then Print and Properties, which are also in Menu ▸ File; Open loses its text, then the theme and help buttons go), the rail's panel buttons scroll when a short window can't hold them with the page navigation, and the text-selection actions wrap so Copy stays on screen. Touch on the page with the Select tool: a one-finger drag pans like the Hand tool, a long press selects the word (instead of opening the page menu) and dragging on extends it, a swipe turns the page in single-page view, and two fingers pinch-zoom without also panning; tools that draw, place or edit keep their drag, and mouse and pen input are unchanged.
- Phones and tablets, continued (`crates/ui-egui/src/narrow.rs`, `fling.rs`, `bar_fit.rs`): crossing below `NARROW_WIDTH` also fits each open document to the page width (View ▸ Fit to width) once per narrow spell, documents opened while narrow included, with an 8-point gutter instead of the 70 that keeps wide pages clear of the floating quick-action bar (the bar floats over the page's edge), so the page spans the canvas; a zoom the user picks while narrow stands, and widening gives every document the zoom it had in the wide window (nothing of this is saved). A quick one-finger pan of the page (Select or Hand tool) keeps gliding after the finger lifts and slows to a stop, as GridCraft's sheet does (same speeds and decay; it stops at the content's edge, when a finger touches the page again, after a pinch, with animation effects off, and when the release turned the page in single-page view). The mode bar sheds controls by measured width at every window width, not only on phones: the search box first shrinks, then becomes an icon, so at 768 points in Vietnamese the mode tabs no longer run under it; a window wide enough for everything is unchanged, and the tab strip likewise.
- Closing and saving, as in the other office forks (`crates/ui-egui/src/closed_docs.rs`, `save_all.rs`, `save_status.rs`, `editing.rs`, `dialogs.rs`, `chrome.rs`): Reopen Closed Tab (Ctrl+Shift+T, File menu, a tab's menu; "Mở lại tài liệu vừa đóng") now works on the web too and brings back the last closed document as it was closed, under its name and unsaved if it was (a "Don't save" is undoable that way). Up to 10 closed documents and 64 MB are kept, oldest dropped first; a password-protected one is kept as its encrypted working file and asks for its password again, and a saved desktop file still reopens from disk. Quit, window close and Close all with several unsaved documents ask once, listing them, with Save all / Don't save / Cancel (one unsaved document keeps the single prompt). On the desktop Save all saves them one after another; on the web each save picker after the first needs its own click on "Save “<next>”" while the list says "— Saved" / "— Saving…", and a cancelled picker or failed write stops there without closing anything still unsaved; a browser without a picker downloads them all on the one click. A document's tab says "Saving…" while the browser writes it and "Save failed" (reason on hover) from a failed save until the next save or edit. Web and desktop alike; the web had no Reopen before, and "Saving…" only shows on the web, where saves wait for the browser.
- Certified and locked forms (`crates/engine/src/certification.rs`, `crates/ui-egui/src/cert_guard.rs`, `forms_ui.rs`): a form field a holding signature locks (FieldMDP `/Reference` Include, Exclude or All, or a signature field's `/Lock`) takes no typing or clicks, is skipped by Tab, and says "This field is locked by the signature of <signer>." on hover and click; other fields fill as before, and the save guard stays the backstop. A level-2 certification greys what it does not permit (comment, Fill & Sign and measuring tools, page edits, content editing, redaction) in the menus, the tool pane and the quick bar, with the reason as tooltip, and drops such a tool back to Select if picked another way; level 3 keeps the comment tools. Its bar names the signer and what is still allowed; viewing, printing, copying, Save As, form filling and signing keep working. Web and desktop alike.
- Find, the Search panel, "Find text and redact" and the `redact_mark` / `text_find` tools match Vietnamese text whatever its Unicode normalization (`crates/render/src/canonical.rs`, `text.rs`): the query and the page text are both composed to NFC before case folding, so a text layer that spells "ử" as "u" + horn + hook above (often one glyph per mark) is found by a precomposed query and the other way round, and the highlight and redaction box cover every glyph of the letter, marks included. Diacritics still count ("a" never matches "ả"). Before, such a line was silently left out of a redaction. Uses the `unicode-normalization` crate (MIT OR Apache-2.0, already in the tree). The Apply redactions confirmation and the notice after applying add that metadata such as the title may still hold the text and suggest Sanitize document (`crates/ui-egui/src/redact_ui.rs`; nothing runs by itself). Web and desktop alike.
- (both) Confirm permanent redaction, remove metadata and hidden data by default, and clear engine Undo/Redo history after Apply so later exports cannot restore redacted content; scripts can explicitly keep metadata.
